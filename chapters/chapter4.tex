\chapter{Compréhension et Acquisition des Données}

\section{Introduction}

Le chapitre d’acquisition et de compréhension des données est essentiel pour établir une base solide pour le système de détection d’anomalies développé pour les transactions SAP. Ce chapitre détaille la collecte, le traitement et l’analyse systématiques des données nécessaires pour comprendre le contexte métier, définir les conditions d’alerte et identifier les schémas de transactions anormales. Il met en évidence l’importance des documents de base de connaissances (KB), élaborés en fonction des besoins métier, qui guident les processus de surveillance et de génération d’alertes.
Dans le cadre de ce projet, trois sources de données hétérogènes ont
été identifiées et exploitées :

\begin{itemize}
    \item Le \textbf{portail SAP Help Portal} — documentation officielle
    SAP accessible via scraping web
    \item Les \textbf{livres techniques SAP} — 298 ouvrages de formation
    au format PDF couvrant les modules BASIS, ABAP, Fiori et S/4HANA
    \item Les \textbf{logs de transactions SAP} — données temps réel
    extraites depuis les transactions SM37, ST22 et SP01
\end{itemize}

\subsection{SAP Help Portal}
% ============================================================

\subsubsection{Description et structure}

Le SAP Help Portal (\texttt{help.sap.com}) constitue la source de
documentation officielle SAP. Il expose une structure hiérarchique
profonde de pages HTML organisées par produit, version et module.
Chaque page contient du contenu textuel structuré (procédures,
paramètres, notes techniques) ainsi que des métadonnées de navigation
(breadcrumbs, liens parent-enfant).

\begin{sourcebox}{Caractéristiques du SAP Help Portal}
\begin{itemize}
    \item \textbf{Volume} : environ 50,000 pages indexées par le sitemap
    \item \textbf{Structure} : hiérarchie à 4-6 niveaux de profondeur
    \item \textbf{Langue} : principalement anglais, avec contenu
    français et allemand
    \item \textbf{Versions} : SAP NetWeaver 7.x, S/4HANA, Fiori
    Launchpad
    \item \textbf{Types de contenu} : procédures pas-à-pas, références
    API, notes de configuration, paramètres de transactions
\end{itemize}
\end{sourcebox}

\subsubsection{Gestion des structures imbriquées}

Le SAP Help Portal présente des structures documentaires imbriquées
à plusieurs niveaux. Notre framework de scraping adresse ce défi par
quatre mécanismes complémentaires :

\begin{enumerate}
    \item \textbf{Breadcrumb Tracking} — maintien du chemin de
    navigation complet pour préserver la localisation de chaque
    document dans la hiérarchie globale. Exemple :
    \texttt{["SAP Fiori Launchpad", "Configuring Roles",
    "Tile Catalogs"]}

    \item \textbf{Relations Parent-Enfant} — capture explicite des
    liens \texttt{parent\_id} / \texttt{doc\_id} entre documents
    principaux et sous-documents, permettant la reconstruction de
    la hiérarchie complète

    \item \textbf{Cross-Reference Mapping} — identification et
    préservation des liens entre documents connexes dans différentes
    sections (liens hypertexte inter-modules)

    \item \textbf{Context Inheritance} — les documents imbriqués
    héritent du contexte pertinent de leurs parents (version SAP,
    module, composants mentionnés)
\end{enumerate}

\subsection{Livres Techniques SAP (PDFs)}
% ============================================================

\subsubsection{Description du corpus}

Le corpus de livres techniques SAP comprend 298 ouvrages de formation
officielle couvrant l'ensemble des modules SAP. Ces documents, au
format PDF, présentent une structure pédagogique standardisée
(unités, leçons, exercices, évaluations) et constituent une source
de connaissance procédurale dense.

\begin{sourcebox}{Caractéristiques du corpus PDF}
\begin{itemize}
    \item \textbf{Volume} : 298 ouvrages, environ 45,000 pages
    \item \textbf{Format} : PDF avec structure hiérarchique
    (chapitres, sections, sous-sections)
    \item \textbf{Contenu} : procédures de configuration, schémas
    d'architecture, tableaux de paramètres, exercices pratiques
    \item \textbf{Modules couverts} : BASIS, ABAP, Fiori, S/4HANA,
    MM, SD, FI, CO, HR, PM
    \item \textbf{Défis techniques} : encodage CID dans certains
    PDFs, espaces manquants dans les polices personnalisées,
    tables des matières indexées comme contenu
\end{itemize}
\end{sourcebox}

\subsubsection{Défis techniques et solutions}

Trois problèmes majeurs ont été identifiés et résolus durant la
phase d'acquisition :

\textbf{Encodage CID dans les PDFs.} Certains livres SAP utilisent
des polices de type CIDFont sans table de correspondance Unicode.
L'extracteur produit alors des séquences \texttt{(cid:127)}
illisibles. La solution appliquée combine une détection par ratio
de contamination (seuil 2\%) et une conversion des codes CID
fréquents vers leurs équivalents Unicode (\texttt{(cid:127)} →
\texttt{•}).

\textbf{Doublons inter-sources.} Le portail SAP Help et les livres
techniques partagent parfois les mêmes procédures de configuration.
7,578 chunks dupliqués ont été identifiés par fingerprint MD5 sur
les 300 premiers caractères normalisés et supprimés, en conservant
le chunk avec les métadonnées les plus riches.

\textbf{Pages QCM de formation.} Les livres techniques SAP incluent
des pages d'évaluation (quiz XTrue/XFalse) sans valeur documentaire
pour le RAG. 5,618 chunks de ce type ont été filtrés par détection
de patterns (\texttt{XTrue}, \texttt{XFalse},
\texttt{determine whether}).

\subsubsection{Transactions surveillées}

Le système surveille en temps réel trois transactions SAP BASIS
critiques pour la santé de l'environnement :

\begin{sourcebox}{Transactions SAP Monitorées}
\begin{itemize}
    \item \textbf{SM37} — Moniteur de jobs batch : suivi des

    analyse des exceptions runtime du système ABAP

\subsection{Pipeline d'extraction temps réel}

L'extraction des données de transactions SAP repose sur deux
mécanismes complémentaires :

\begin{enumerate}
    \item \textbf{Appels RFC/BAPI} — connexion directe au système
    SAP via l'interface Remote Function Call. Les BAPIs standards
    \texttt{BAPI\_XBP\_JOB\_SELECT} (SM37) et
    \texttt{BAPI\_ABAP\_DOCU\_GET} (ST22) sont utilisés pour
    extraire les données sans modifier l'état du système

    \item \textbf{Polling périodique} — interrogation toutes les
    5 minutes pour les jobs actifs, toutes les 15 minutes pour
    l'historique des dernières 24 heures
\end{enumerate}

\begin{remarquebox}
Les logs de transactions constituent la source de données
\textbf{dynamique} du système, par opposition aux sources
documentaires statiques (Help Portal et PDFs). Ils alimentent
le contexte situationnel du RAG : lorsqu'un consultant interroge
le système sur une erreur SM37, le contexte du job en erreur
est automatiquement injecté dans le prompt de génération.
\end{remarquebox}

\section{Bilan de la Phase d'Acquisition}
% ============================================================

La phase d'acquisition et de compréhension des données a permis de
constituer un corpus de \textbf{105,331 chunks indexables} à partir
de trois sources hétérogènes, après application de huit corrections
qualité motivées par des diagnostics empiriques sur les données réelles.

Les principaux enseignements de cette phase sont :

\begin{itemize}
    \item La \textbf{diversité des sources} (documentation officielle,
    livres de formation, logs temps réel) est un avantage différenciateur
    majeur : le système peut répondre à la fois à des questions
    procédurales, conceptuelles et situationnelles

    \item La \textbf{rigueur du nettoyage} (8.3\% de chunks supprimés
    ou corrigés) garantit que le retrieval ne sera pas pollué par du
    bruit sémantique (QCM, doublons, contenu illisible)

    \item L'\textbf{extraction des 2,794 T-codes} avec support des
    namespaces (\texttt{/UI2/NWBC\_CFG\_CUST}) constitue un avantage
    clé pour la recherche hybride BM25 : les identifiants SAP exacts
    sont préservés et indexés

    \item La \textbf{structure hiérarchique préservée} (breadcrumbs,
    parent\_id, position) permettra d'enrichir le contexte de retrieval
    au Sprint 4 par injection du contexte parent
\end{itemize}
